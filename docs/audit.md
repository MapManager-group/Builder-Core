# BuilderCore 2.2.1-snapshot 代码审查

审查日期：2026-10-28。按单台 Paper 建筑服务器、玩家交互与低频位置命令审查全部生产源码、命令声明、配置和文档。没有增加依赖、启用未开放功能或修改权限包。

## 命令与帮助

全部命令统一注册补全，按当前参数前缀、入口权限和玩家可见性过滤；不回退到默认玩家列表。补齐飞行目标、管理目标、属性数值、颜色、形变轴线和 WorldEdit 转发参数。已有时间、天气、模式补全继续复用；家补全不查询远程玩家，也不创建离线档案。新建家、传送点和别名仍为自由文本。

无参数和固定参数命令可用 `/<命令> --help` 显示用法与别名，`/buildercore help [页码或命令]` 提供管理目录。用法来自 `plugin.yml`，参数占位符按普通文本显示；`help` 仍可用作家或传送点名称。家、传送点、物品名和 WorldEdit 转发参数保留 `--help` 的原有字面含义，不会被全局帮助截获。

## 已修复的问题

| 问题与触发条件 | 原来的影响 | 修复 |
| --- | --- | --- |
| 传送点别名写入和加载方向相反 | 重载后别名失效，列表和删除不一致 | 统一“别名 → 正式名称”，保留角度小数，删除时清理所有关联别名，命令阻止歧义别名，API 保留覆盖写入 |
| 家数量权限没有检查布尔值 | 否定的 unlimited/数字节点仍增加配额 | 只统计有效授权；设置和列表读取时刷新配额 |
| 家的每次修改启动独立异步任务，共用 YAML 对象 | 快速新增/删除及重载可能写入旧状态；保存失败仍提示成功 | 保存完成后更新内存，用临时文件替换原文件；加载错误保留原文件并停止，不覆盖损坏数据 |
| 世界晚于位置数据加载 | 缓存中的空世界在后续加载后仍无法使用 | 取位置时重新解析世界，保留原有位置对象接口 |
| 家与部分 TP/传送点在传送结果返回前提示成功 | 保护插件取消后仍显示成功 | 根据实际传送结果反馈；失败和异常明确提示 |
| `/back` 记录被取消的传送，返回本身又写入历史，提前弹出记录 | 记录重复、来回跳转、失败丢失历史 | 在未取消传送的 MONITOR 阶段记录；返回期间不入栈，成功后才消费历史 |
| 非有限坐标、尺寸和距离；形变缩放为零 | 无效值传入服务端或 WorldEdit | 在输入边界拒绝 NaN/Infinity 和零除数，保留合法范围 |
| 入服等待数据库查询时未限制玩家；同意未等保存完成 | 查询窗口可使用服务，数据库写入失败后仍放行 | 先设置入服限制，再独立加载家数据，损坏的家数据不打断协议链路；同意保存成功后才解除；失败提示重试，延迟查询不覆盖已成功的同意 |
| 数据表异步创建与首次查询无先后保证，SQL 错误被吞掉 | 初始化阶段查询失败、写入失败表现为成功 | SQL 操作等待建表结果；错误沿原有 Future 返回给调用者 |
| 协议命令使用 startsWith，命名空间命令不匹配 | 相同前缀的其他命令被放行，合法命名空间命令被拦截 | 按完整命令根匹配协议命令；协议开关变更提示重启并保留当前运行状态 |
| 光源、管理员方块、刷怪蛋和动物调整未完整尊重保护/双手事件 | 已取消交互仍可能改动世界，副手事件重复调整 | 检查有效手与取消结果，光源补齐权限；刷怪蛋派发实体放置事件，并检查实际实体类型 |
| 生物双击移除绕过伤害取消，并包含玩家类型 | 持剑或保护拦截后仍可能直接移除目标 | 在 HIGHEST 尊重取消，排除玩家；保留原有两次确认和权限要求 |
| 双层半砖沿射线只查找 6 格 | 更远距离可能拆错半层 | 使用服务端碰撞射线，在现有最大交互距离内定位命中面 |
| 菜单打开后权限变化 | 仍能从已打开菜单领取物品 | 在点击事件边界检查当前菜单权限 |
| 受限命令只匹配整条输入 | `/help 1`、`/bukkit:plugins` 等可绕过 | 统一匹配命令根和命名空间形式，保留 bypass 权限 |
| 自动 AFK 重复注册，异步写普通 Map，退出不清理；代理异步调用玩家/PAPI | 重复处理、保留离线记录、跨线程调用平台 API | 自动 AFK 沿用 PAPI 启用条件且只注册一次，在主线程更新与清理；代理消息使用同步定时任务；手动 AFK 不再被定时检查立即清掉 |
| 请求、飞行缓存缺少清理，重复代码分散 | 过期请求和离线数据保留；维护时容易只修到一处 | 定时清理过期 TPA，离线清理关联请求/飞行状态，复用无状态 NoClip 实例，合并速度与攻击保护重复逻辑、珊瑚监听共用实现并保留旧入口 |
| 背包反序列化吞掉损坏数据 | API 调用者可能把空数组误当正常背包 | 按已有 IOException 契约报告错误，保留原序列化格式和方法签名 |
| 未注册的投票/鹦鹉源码有明确错误 | 若以后调用，会出现反向权限、重复赞成计票、空肩膀异常 | 修正这些实现；仍不注册或开放命令 |

## 二次审查与兼容性修正

本轮按原始 2.2.0 构建和 Git 基线复查差异，修正上一轮引入或遗漏的问题：

最终比对通过：原有 82 个类的 308 项公开/受保护成员均保留；Git 基线中的命令名称、别名、入口权限、权限包和插件依赖声明未改变。`2.2.1-snapshot` 已重新打包，离线回归、打包 JDBC 检查与隔离 Purpur 1.21.11 事件检查均通过。

- 恢复合法 `--help` 家名、传送点名、物品名和 WorldEdit 原始参数；只给不会与合法参数冲突的命令添加帮助标记。
- 恢复 `AFKListener.beforePlayerJoin(AsyncPlayerPreLoginEvent)`、`Misc.onBlockFadeEvent(BlockFadeEvent)` 公开方法与 AFK 构造器注册行为；自动 AFK 继续遵守原有 PAPI 启用条件。
- `HomeDataLoader.getHomes()` 保留可变实时视图，`WarpDataLoader.getWarps()` 保留可变快照；位置读取保留原对象，且只在世界尚未解析时补齐世界，不覆盖 API 调用者对已有世界的修改；`addWarp` 保留 API 覆盖写入。重名校验留在命令入口。
- 修复旧 YAML 中大写/混合大小写家名的世界解析、覆盖和删除；恢复离线玩家现有家档案的补全，损坏档案不使补全抛异常。
- 恢复副手刷怪蛋和潜影盒/末影箱快捷打开，仍防止主副手重复触发；实服检查覆盖副手刷怪蛋与潜影盒预览。
- 光源、半砖及实体操作在 HIGHEST 保护处理完之后执行，避免晚注册的保护监听器尚未拦截时已修改世界；实服回归加入晚注册 HIGHEST 保护。
- `/back` 只跳过自己的目标事件，按原记录对象消费历史，不再丢失返回等待期间其他传送的记录；主线程完成结果不额外推迟一 tick。
- 校正四参数 TP 补全的权限分支与 WorldEdit replace 帮助的可选源方块参数。

## 保留的权限边界与风险

- **数据库传输**：原 JDBC URL 仍含 `useSSL=false&allowPublicKeyRetrieval=true`，本次没有更改部署连接要求。跨不可信网络连接 MySQL 会暴露传输与身份验证风险，应使用受控本地/私网或加密隧道。没有验证线上 MySQL、证书或依赖漏洞公告。
- **管理权限**：`invsee` 与 `endersee` 打开真实库存，拥有相应权限的玩家可增删物品；`whois` 会显示 IP、UUID 和位置。这些是既有管理功能，不能向普通玩家授予对应管理权限。
- **世界准入**：MMC 检查只覆盖既有 TP/TPA 路径。家、公共传送点、返回、其他插件的传送需依靠世界管理插件的全路径准入保护。没有将本次审查扩展成新的世界访问策略。
- **建筑与实体**：刷怪蛋和双击清除延续既有放置权限模型，拥有建筑权限意味着可生成/移除生物。坐垫放置/拆除派发保护事件，移动仍只检查坐垫权限、世界及区块边界；区域插件对移动的规则需要联调。
- **本地持久化**：位置命令同步保存，小文件、低频调用适用；大量自动化写入会占用主线程。背包旧序列化 API 使用 Java 对象流，只能读取可信本地数据，不能作为接收不可信外部数据的接口；该 API 当前未接入玩家恢复链路。
- **兼容性**：公共/私人权限包、旧旁观权限额外检查、`tpignore` 的单参数 TP 范围保持原样。既有名称中的点号拆分损坏不会自动迁移。协议开关、数据库连接与 WorldEdit 快捷命令注册变化仍需重启。
